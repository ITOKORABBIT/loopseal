# 工作紀錄 `.ai-workflow/`

只有需要時才建。判斷見 SKILL.md 第 9 節。

## 原則

- **人看得懂優先**：Markdown，不用 JSON。使用者要能自己打開讀。
- **輕**：只記「判斷現況」需要的東西。這不是專案管理系統。
- **就近**：放在工作所在的資料夾，不集中在某個中央位置。
- **不取代**使用者既有的筆記系統或交接流程。這是工作進行中的即時紀錄。

## 結構

```
.ai-workflow/
  state.md        目前任務：進度、已驗證、尚未驗證
  handoff.md      最新交接（新的加在最上面，舊的往下壓）
  evidence/       指令輸出、截圖、產出快照
```

沒有資料夾可放的工作（純對話研究、一次性協助），把交接區塊直接寫在回覆裡。

## `state.md` 範例

```markdown
# 工作狀態

> 更新：2026-01-15 14:30　by <Agent>

## 修好登入頁
- 類型：程式
- 進度：**已測試，尚未部署**
- 驗收標準：使用者用手機能登入並看到訂單列表

### 已完成並驗證
- [x] Implemented — 改 `src/login.js:20-55`
- [x] Tested — `npm test` → 45 passed，輸出 `evidence/2026-01-15_test.txt`

### 尚未完成
- [ ] Deployed — 未做
- [ ] Human Verified — 未做（只有使用者本人能給）

### 尚未驗證
- UNVERIFIED：手機實機沒測過，只測了桌機瀏覽器 → 需要實機或模擬器

### 已知問題
- 密碼錯誤時訊息還是英文，未處理（不在本次範圍）
```

## 維護規則

1. **狀態改變的當下就更新**，不要等收尾補記。
2. 每個任務一定要有「尚未驗證」一節；沒有就寫「無」。空白會被誤讀成全部驗過。
3. 退回時把勾拿掉並記一行原因，不要把歷史洗掉。
4. 結案後保留紀錄，不要刪——下次出問題時它就是現場紀錄。
5. 檔案太長時，把已結案的搬到 `.ai-workflow/closed.md`。

## 要不要進版本控制

預設**建議提交**：讓下一個接手的人 clone 完就看得到現況。

但先確認兩件事：紀錄裡不要寫入密碼、token、客戶個資；公開 repo 要避免內部路徑與人名。有疑慮就把 `.ai-workflow/` 加進 `.gitignore`，並在交接裡說明紀錄放在哪。
