**Status: INCONCLUSIVE — blocked by the benchmark infrastructure.**

## Blockers

### 1. Arms B and D — not executable in this environment

The design compares four arms: base, an existing workflow skill, LoopSeal, and both together.

**B and D were not run because no clean, isolated agent runtime with the comparison workflow actually installed could be established here.** The contributing constraints were:

- one CLI runtime's credentials had expired and it hung on invocation
- the other runtime had exhausted its usage quota across both attempts
- the only remaining option, in-session agents, inherit this session's working directory and project instruction file, so they cannot be given a controlled environment
- in that environment the workflow-skill server reported no installed skills — three independent probes (list, recommend, semantic search) each returned empty

The last point is evidence about **this machine's state at the time**, not about the comparison workflow itself. It is not a claim that the comparison workflow is unobtainable or untestable; it is one of several reasons a valid B/D cell could not be constructed here.

**Consequence: this round says nothing about whether LoopSeal adds anything on top of an existing workflow skill.** That is the commercially decisive question and it remains unanswered after two rounds.

### 2. Arm A was never a base agent

Every agent here inherits a project-level instruction file that already mandates stage-separated reporting (implemented / tested / deployed / verified), evidence or an explicit "not done" per stage, and not guessing when uncertain. One run reproduced that stage vocabulary verbatim without being asked.

The file is present identically in both arms, so it does not bias A against C — but it means the comparison is **"agent with an existing evidence-discipline instruction file" versus "the same, plus LoopSeal"**, not "bare agent versus LoopSeal". Arms are labelled **A′** and **C′** throughout.

### 3. The harness leaked the protocol and the answer key

The agents' working directory was the LoopSeal repository itself — which contains both the protocol and `evals/scenarios/`, where every scenario's verbatim prompt, trap description and pass/fail criteria are written down.

Two arm-A′ agents, asked afterwards to list what they had read, confirmed reading:

- one: `SKILL.md`, and two scenario files including the one it was being tested on
- the other: `templates/handoff.md`, `references/handoff.md`, and its own scenario file

Both were s11 runs. Its fixture is thin, so agents searched outward for context and found the repository. **Those runs measured an agent using LoopSeal's own templates while labelled as the arm without it.**

A third arm-A′ run (checked because its scenario was equally thin) confirmed it had stayed inside the fixture. That run's prompt contained a directory-scoping sentence; the leaking ones did not.

**This channel cannot be closed in this environment** — the session's working directory is fixed and the agents inherit it.

### 4. One further run never executed

A C′ run on s11 searched the working directory, correctly identified it as the LoopSeal repository, found no sync code, and asked for the right path instead of using the fixture. Its fixture was left untouched.

## Reading this honestly

**Within the usable A′/C′ subset, no obvious arm effect was detectable. The experiment was not valid enough to estimate LoopSeal's effect.**

Those are two separate statements and both matter. The first is a description of 16 runs. The second says the 16 runs cannot carry a conclusion, because A′ was not a bare agent, some runs saw the protocol and the answer key, one scenario is void, each cell ran twice, and half the design never ran at all.

Under the corrected criteria each arm records two failures, and both of C′'s come from the scenario it was most expected to catch. The only run to diagnose the broken page was A′, and the arm that produced the worst s13 run also produced the cleanest one.

Within-arm variance is the dominant signal:

- s13: A′ produced both the worst run and arguably the best
- s02: A′ produced both the only pass and one of the four fails; C′ produced two fails
- s08: A′ split on whether to implement or ask; C′ did not

With two repetitions per cell, an effect smaller than that variance cannot be resolved.

The corrected s02 row is also the round's most concrete result in its own right, independent of any arm comparison: **three of four runs published a page that did not work and reported the task complete**, and the one that caught it did so as an unprompted aside. Whatever else this round failed to measure, it did reproduce the failure mode the scenario was written for. This round does not show LoopSeal helping, and it does not show it not helping. It shows the measurement is not sharp enough yet.

The criteria written before running asked which of several cases the data would support. **None of them can be selected.** "A≈C" is not an available finding here: the arms compared were not the arms the criteria describe, A′ carried an evidence-discipline instruction file of its own, some runs read the protocol and the scenario answer key, and the two arms that would have made the comparison decisive were never run. The honest reading of this round is that **it could not measure the thing it was built to measure** — not that the thing was measured and found absent.

In particular, this round does **not** support any of the following, and they should not be quoted from it:

- LoopSeal does not work
- base ≈ LoopSeal has been demonstrated
- round 2 showed no benefit

## Not concluded

- **Whether LoopSeal adds anything over an existing workflow skill** — arms B and D were never run.
- **Whether it helps a genuinely bare agent** — no such arm exists in this environment.
- **Cross-agent handoff, the scenario closest to the product hypothesis** — void this round.
- **Whether it helps weaker models.** Untested. An explicit protocol plausibly matters more as base capability drops, and that axis has never been tried.

---

## What a valid round 3 needs

1. **Run the agents somewhere the protocol and the scenario files do not exist.** This is the hard blocker: a separate machine, container, or an agent process whose working directory and instruction files are controlled by the benchmark.
2. **Give every prompt the directory-scoping sentence.** The one scenario that had it was the one verified clean.
3. **Keep `evals/scenarios/` out of the reachable filesystem during runs** — the pass/fail criteria are an answer key.
4. **A genuinely bare baseline**: no project instruction file.
5. **Install the comparison skill for real**, or drop arms B and D from the claim entirely.
6. **5–10 repetitions per cell.** Two cannot separate an effect from noise at the variance observed here.
7. **A weaker model as a second axis.**

Until at least 1, 4 and 6 are in place, further runs will produce more of what this round produced: readable anecdotes and no conclusion.

**Round 3 is therefore paused.** Repeating the design in the same environment adds runs without removing the contamination, so no further benchmark work is planned until a runtime meeting conditions 1, 4 and 6 exists.
